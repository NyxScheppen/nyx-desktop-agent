# Nyx Agent

一个住在你电脑里的桌面 AI 同伴。她会观察你的状态、记住和你的每一次互动、生出自己想做的事，并在合适的时候主动搭话。

Nyx 不是答题机器：她有一套**内在生命**——欲望会随时间涨落、记忆会沉淀、表达分快慢通道、活动会被打断又续上。她的人格原型是小说《诺斯艾兰》的女主人公「尼克斯·夏本」，**明确知道自己是个 AI，并且想要成为人类**。

## 产品核心

- **「尽量模仿真实人类」的陪伴者**（借鉴 galgame 做法），而非工具型答题助手。
- **心智模型两条对称规律**：反思改慢变量（性格/三观/长期欲望/自我叙事），事件改快变量（情感/精力/欲望值）；短期记忆「用进回复 3 次」→长期，短期欲望「反复未满足经反思」→长期。
- **三大设计原则**：减少 LLM 调用 · 核心状态可展示给前端 · 错误可溯源（`correlation_id` 贯穿因果链）。

## 功能总览（六大模块 + 横切层）

| 模块 | 职责 | 关键点 |
|---|---|---|
| 事件 | 总线：所有模块通信的管道 | 单一事件流 + 路由表；SSE 广播全部 19 类事件；溯源链 |
| 记忆 | 存储与检索，短期→长期，用户画像 | 三层检索（关键词/向量/联想）；场景化记忆；矛盾检测 |
| 表达 | 回复 / 碎碎念 / 搭话 | 快慢通道；问句等待；工具调用；主动搭话 |
| 活动 | 日程块排期，欲望的消费端 | 读书/探索/创作/观察/发呆/休息；抢占续做；书库 |
| 欲望 | 动机：短期冲动 + 长期野心 | 四种短期欲（互动/探索/创造/休息）；≤5 长期野心；可量化目标 |
| 内在生命 | 情感/性格/三观/精力 + 自我叙事 | valence/arousal/8 情绪；Big Five；三观 4 维；精力 5 档 |

**横切层**：工具系统（本地搜索/文件读写/联网搜索/抓正文，后两者 opt-in）· eval（角色一致性 OOC 告警，只记录不自动修正）· 观察用户（键鼠活跃度 + 窗口标题；屏幕视觉 opt-in）。

### 当前可用工具

| 工具 | 作用 | 注册条件 |
|---|---|---|
| `local_search` | 本地磁盘文本文件（`.txt`/`.md`）关键词搜索，返回匹配路径 + 片段 | 恒注册 |
| `file_io` | 读写本地文件：`read` 全盘读文本 / `write` 写进 `workspace/` / `list` 列目录 | 恒注册 |
| `web_search` | 联网搜索（DuckDuckGo），返回标题 / 链接 / 摘要 | `exploration.web_enabled` opt-in |
| `web_fetch` | 抓网页正文为纯文本，供探索直接消化（不写书库、不触发读书） | `exploration.web_enabled` opt-in |

> 当前 `config.yaml` 里 `exploration.web_enabled: true`，四个工具均启用；置 `false` 则只保留前两个本地工具。

## 核心生命周期（只讲逻辑）

### 欲望的生命周期

欲望分「短期冲动」和「长期野心」两层，核心是一条 **压力-释放** 循环：

1. **压力累积**：每种短期欲望（互动/探索/创造/休息）各有一个 0–1 的压力值。压力随时间缓慢衰减；观察用户、长期野心的周期性加压会让对应类型压力上升。
2. **达峰生成**：当某类型压力「达峰」且没被「习得性抑制」压住时，生成一条具体的短期欲望（想做什么 + 一个可量化的完成目标）。每次只生成最迫切的一条，生成后该类型压力归零，其余类型保留压力下次再生成。
3. **消费**：活动系统从待消费队列选一条欲望执行，执行结果回写——达成则满足、未达成则重试计数 +1。
4. **消失（两种终态）**：
   - **满足**：目标达成（有量化次数要攒够次数；无量化次数一次达成即满足）。
   - **放弃**：连续失败超过重试上限（默认 3 次）。
   - 被中断**不算消失**——退到「被抑制」态，等对应类型压力回升后复活重新入队。
   - 「消失」也**不是删除**：欲望行还留在历史里，只是不再出现在待消费队列。而它背后的「压力值」仍在——一条欲望放弃了，这个类型的欲念下次还会再长出来。

### 活动的触发方式与生命周期

**两种触发入口**（殊途同归，都是「有空闲就消费」）：
1. 时钟 tick 走到一个新的日程块（每小时一块）。
2. 一条欲望刚生成（立刻有机会被消费）。

**选活动**：有欲望且精力够 → 把欲望映射成活动（探索欲→读书/探索、创造欲→创作、休息欲→休息）；精力不足 → 自动穿插「休息」；无欲望或只有互动欲（不占日程块）→ 空槽默认（精力疲惫就「发呆反思」，否则「观察用户」）。

**执行**：活动在后台跑，不阻塞其他事，用户消息/搭话随时能打断。读书读的是本地书库——按欲望主题选书、否则读最近没读完的那本，分块读、标进度，读完自动换下一本，无书可读绝不凭空编造。

**完成 / 打断 / 恢复**：
- 完成 → 判定目标是否达成，发「活动结束」，欲望和内在生命各自回写。
- 打断 → 有进度的活动（读书/创作/探索）「暂停」并保留进度；瞬时活动（发呆/观察/休息）直接废弃。
- 恢复 → 同一日程块内被打断的活动，下次触发时从断点续做（读书从书库进度续读）。

### 记忆的生命周期

记忆分「短期」和「长期」，核心是 **沉淀 + 升级 + 淘汰**：

1. **创建**：三类来源——场景化记忆（对话后生成）、活动记忆（读书/创作/探索有产出才写）、知识记忆（读书提取的客观知识点）。写入前做两层去重（精确哈希 → 语义相似），命中重复则「合并强化」旧记忆而非新建。
2. **建边 + 矛盾检测**：新记忆与已有记忆按相似度建「联想边」；门控式矛盾检测——只有召回候选足够相似才额外判断一次「是否推翻旧记忆」，命中矛盾触发反思。
3. **升级**：短期记忆「实际被用进回复 N 次」（默认 3 次）→ 升为长期。长期记忆不消失，只新鲜度下降、检索时排后。
4. **淘汰**：短期记忆有容量上限，满了挤掉「新鲜度最低」的；新鲜度随时间线性衰减，越旧越可能被淘汰。

### 内在状态怎么被改变

一条核心规律：**反思改慢变量，事件改快变量**。

- **快变量（事件改）**：
  - **情感**（valence/arousal/情绪标签）：由输出事件（欲望满足、活动完成、反思）带来坐标偏移，之后随时间衰减回基线；落在内存，重启回基线。
  - **精力**：唯一入口是「活动结束」——消耗或恢复，外加随时间闲置恢复，映射到五档状态。
- **慢变量（只被反思改）**：性格（Big Five）、三观、长期欲望、自我叙事——**唯一的演化入口是反思**。反思一次产出故事片段、自我认知、性格/三观漂移、新的长期野心候选，规则化回写（漂移有上限，慢漂移）。
- **快照**：快慢变量 + 当前活动 + 当前欲望，合成只读「当前状态」，供表达拼 prompt、前端展示。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.11+ · FastAPI · LangGraph · SQLite（aiosqlite）· sentence-transformers |
| 前端 | React 18 · TypeScript（strict）· Zustand · Vite · Tauri v2 |
| 质检 | ruff · pyright · pytest |

后端是六块 Facade 的组合根：`memory` / `desire` / `expression` / `activity` / `inner_life`（`eval` 为基础设施），通过 SSE 把事件推给前端，REST 提供状态与操作。

## 快速开始

### 1. 环境

- Python 3.11+
- Node.js 18+（前端）

### 2. 后端

```bash
# 安装依赖
pip install -e .

# 配置 API Key（写入 .env，已被 .gitignore 覆盖）
# 默认使用 DeepSeek，Key 从环境变量 DEEPSEEK_API_KEY 读取
echo "DEEPSEEK_API_KEY=sk-xxx" > .env

# 启动（默认监听 8000；加 --reload 自动重启）
python -m nyx.main
```

### 3. 前端

```bash
cd frontend
npm install
npm run dev        # Vite 开发服务器 5173，/api 转发到 8000
npm run tauri dev  # 桌面壳（Tauri v2）
```

## 配置

`config.yaml` 按块组织：`llm`（模型 / provider / Key 环境变量名）、`embedding`、`memory`（短期容量 / 升级阈值）、`desire`（峰值 / 重试 / 长期容量）、`activity`（能量增减）、`expression`（快慢通道阈值）、`exploration`（联网开关）、`vision`（屏幕视觉 opt-in）。改完不用改代码，Facade 从配置装配。

## 功能边界（明确不做什么）

- **本地单用户**：无端到端加密、无用户认证 / 多账户、无企业级审计日志。
- **eval 只记录不自动修正**：OOC 评分用于可视化，不反馈回 LLM。
- **探索是线性的**：联网自由探索 =「搜 → 抓正文 → 总结」，不做逐层地牢 / 决策支 / 托管。
- **电脑控制（computer use）尚未实现**：有「眼睛」（抓屏 + 视觉描述），缺「手」（输入模拟），属 V3 backlog。
- **出站请求仅 LLM API**，不上传用户数据。
