# 文档指令

适用于 `docs/`，也供代码任务查阅契约和同步文档时使用。与根通用规则共同使用。路径均相对仓库根目录。

## 参考索引

所有设计、事实摘要和实现索引集中在 `docs/`。开始工作前先按本节定位相关资料，不要凭空重新设计。

### 读取与同步规则

- 改 `nyx/memory/` 或记忆契约前，必须先读记忆事实摘要和完整契约。
- 改 `nyx/activity/`、欲望消费、活动打断/恢复、自由探索、活动书库、活动时间线或
  `activity_*` 事件前，必须先读活动事实摘要和完整契约。
- 改欲望产生、压力、消费、满足/淘汰或 `desire_*` 事件前，必须先读欲望事实摘要和完整契约。
- 改内在生命前，必须先读内在生命事实摘要和完整契约。
- 改表达系统或表达侧阅读交互前，必须先读表达事实摘要和完整契约；不得引用已删除的表达旧 spec。
- 改 `nyx/events/`、`nyx/subscriptions.py`、`nyx/runtime.py`、`nyx/app_context.py`、
  `nyx/main.py`、事件相关 DB 表、模块总线通信或跨模块副作用前，必须先读总线事实摘要和完整契约。
- 总线完整契约重于其他旧文档；涉及总线契约覆盖的功能时，必须同步更新
  `docs/specs/04-module-bus-system.md` 和 `docs/facts/module-bus-system-facts.md`。
- 改动已有文档契约覆盖的功能时，必须同步相关文档；若要改变既有文档语义，先询问用户。

### 对象完整性审计

“对象”指会持久化或跨 API、事件、Facade、后台任务、前端 store 流动的领域对象，
例如书籍、材料、任务、事件、进度和记忆；局部变量与单次函数内部中间值不在此列。

新增或修改对象时，必须先在对应唯一完整 spec 中记录以下内容：

1. **入口清单**：所有能产生、导入、恢复或重放该对象的 API、事件、迁移、后台任务和内部调用。
2. **消费者清单**：所有需要查询、发现、选择或使用该对象的后端模块、LLM 上下文、事件订阅和前端 store。
3. **状态迁移表**：全部持久状态、迁移条件、副作用，以及失败后的落点。
4. **Bad case 表**：逐项覆盖空、失败、部分完成、乱序、重放、删除。

不适用项必须写明“不适用”及原因，不能静默省略，也不能为了填表虚构状态或错误路径。
增加写入口时要核对全部旧消费者，增加消费者时要核对全部旧数据来源。跨存储的同类对象必须在
消费侧形成明确的统一候选集；没有匹配证据时，不得用“最新一条”等兜底替用户做决定。

反例：阅读器上传的 EPUB 与活动材料来自两个写入口。探索欲选材必须枚举两套书库并使用同一
匹配规则；主题无匹配时进入既定搜索路径，不能回退为读取最近上传材料。

## 文档维护

- `docs/test-inventory.md` 是当前测试快照，不是变更历史；修改测试后更新文件数、覆盖范围和关键回归名称。
- 审查前查 `docs/LessonsLearned.md`，发现可复用错误类型后追加或更新教训。
- 移动文档后按新目录检查内部相对链接、所有引用方和已删除文件引用。
- 文档所述验证命令按涉及的前后端范围执行；不得以事实摘要、导航索引或产品愿景覆盖完整契约。
