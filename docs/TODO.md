## 最紧急（P0）

以下事项来自 2026-11-09 云端取证，按先恢复稳定性、再改善探索与费用的顺序处理；实施与发布仍按开发约定审核。

- [ ] **共享数据库锁超时修复的云端发布与验收（本地实现完成）。** 当日 09:32（北京时间），OneBot outbox 领取任务等待共享锁超过 3 秒，`TimeoutError` 逃逸至角色运行循环，导致角色 `FAILED`、业务接口返回 503，但 Railway 部署仍显示成功。区分锁等待与其他数据库失败，对可恢复锁争用在传输内部退避重试；覆盖扫描、领取、发送后确认及退出清理，保持取消传播和持久队列恢复语义。补充异常类型与锁等待/持锁诊断；当时的具体持锁操作尚未确定。本地已完成分阶段退避、发送后仅重试确认、连接重建保留确认状态及有界清理，并通过真实锁争用和恢复回归；待发布后在云端验收：制造锁争用后角色仍可提供服务，锁释放后队列恢复，发送后确认超时不立即重复外发。
- [ ] **SSE 请求放大修复的云端验收与记忆分页（本地首批实现完成）。** 初次连接最多回放 1000 条事件，当前逐条触发记忆、活动等快照刷新；云端约 27 秒内出现 75 次记忆相关 GET。明确回放与实时边界，回放完成后集中同步快照，合并同类刷新并约束并发；历史事件不重复触发完成气泡。缩减记忆接口载荷，避免将 embedding 传给展示端，按需分页。本地已接通有限回放边界、完成帧集中同步、同模块在途合并与末次补刷、角色代数隔离及展示字段投影；1000 条历史事件回归通过。完整分页留待后续切片，发布后还需云端验收：1000 条回放不会按事件数增加快照请求，断线重连、回放期间新增事件与角色切换均不丢消息、不串角色。
- [ ] **修复搜索偏题与无关资料先入库的问题。** 云端已复现 Bing RSS 查询正确但结果无关；现流程先消化、抽事实并入库，最后总结才发现偏题。增加入库前的相关性与来源质量判断，明确正文失败/摘要降级，检查工具业务结果而非仅看调用是否抛异常；无关或不可读来源不产生知识，必要的补搜受预算约束。验收覆盖偏题结果、空正文、摘要回退与部分来源可用。
- [ ] **让探索选题承接历史并支持深入。** 云端 79 条探索记录中，“痛苦”36 次、“道德”28 次；76 次已完成探索中 75 次为 `exhausted`。生成时采样类似历史探索的结论、失败原因和待解问题，改进同分选题及历史去重；后续搜索落实具体问题，按新证据继续追问，受次数/费用预算约束。验收以真实模型行为评测确认减少重复、增加有效进展。
- [ ] **补全探索实际行动链与前端展示。** 显示实际搜索词、访问 URL、来源、阶段、结果和失败/降级原因；接通已有工具轨迹展示能力，覆盖运行中、失败与暂停状态。区分生成的行动描述与实际执行，避免把“想翻阅旧日记”展示成已经实施的行为。
- [ ] **控制后台模型调用及常驻资源费用。** 本次模型账本去重后为 1073 次调用、约 146 万 token，漫游碎碎念约占 33%，矛盾检查约占 17%，事实抽取约占 14%；一次无关探索仍产生 15 次调用。核对必要性、重复抽取及累计预算，提供模块/活动用量归因。Railway 本账期该项目约 3.85 美元用量中约 85% 为内存；后端过去 24 小时平均约 1.18 GB，NapCat 当前约 620 MB，需实测定位内存组成后优化。模型 token 账本与供应商实际账单分开核对。
