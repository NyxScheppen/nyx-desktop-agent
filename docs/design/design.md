# Nyx Agent 系统设计

> 桌面陪伴 Agent —— "住在电脑里的同租者"。人格来自小说女主人公，明确自己是 AI、希望成为人类。
> 本文档定义系统架构与六大模块设计；每项功能的实现 spec 遵循 `../spec-template.md`。

## 1. 概述

### 1.1 定位

- 日常使用 + Python 求职作品集
- 核心是"尽量模仿真实人类"的陪伴者，借鉴 galgame 做法

### 1.2 设计原则（贯穿全部设计）

1. 减少 LLM 调用
2. LLM 调用透明化，token 消耗可查可追溯
3. 所有设计可展示给前端
4. 对所有 LLM 产出和行动有 eval 评分
5. 错误可溯源

### 1.3 模块总览

**六大模块**：

| 模块 | 一句话职责 |
|---|---|
| 事件 | 总线：所有模块通信的管道 |
| 记忆 | 存储与检索，短期→长期，用户画像 |
| 表达 | 回复 / 碎碎念 / 搭话 |
| 活动 | 日程块排期，欲望的消费端 |
| 欲望 | 动机：短期冲动 + 长期野心 |
| 内在生命 | 数值：情感/性格/三观/精力 + 自我叙事 |

**两个横切层**（非模块，被模块共用）：

- **工具系统**：工具注册/执行（被表达、活动共用）
- **eval 体系**：对所有 LLM 产出的评分与记账

### 1.4 心智模型（两条对称规律）

> **反思改慢变量，事件改快变量**
> - 慢变量（性格、三观、长期欲望、自我叙事）← 只被反思改
> - 快变量（情感、精力、欲望值）← 被输出事件改

> **短期→长期 升级同构**
> - 记忆：短期 --"实际用进回复 3 次"--> 长期
> - 欲望：短期 --"反复出现且未满足，经反思"--> 长期

## 2. 技术选型与进程边界

| 层 | 选型 |
|---|---|
| 核心逻辑 | Python 3.11+，严格类型注解 |
| 前端 | TypeScript/React（strict） |
| 桌面壳 | Tauri（薄壳，只做窗口/托盘/通知） |
| 编排 | LangGraph（仅回复流程、跨域行为链两处图） |
| LLM 客户端 | LangChain 集成，默认 Deepseek，可改配置 |
| 工具调用 | LangChain 集成 + 手写 tool schema |
| 向量 | 本地 sentence-transformers embedding |
| 持久化 | SQLite |
| 记忆关联图 | networkx（内存） |
| 事件总线 | asyncio 队列 + 路由表 |
| 前端通信 | SSE over localhost |

**进程边界**：Python 核心作为**独立本地服务**运行（`uvicorn`），Tauri 壳 + React 前端通过 localhost HTTP/SSE 连接。开发时手动起服务；不打包 sidecar。

**运行驱动**：混合——时钟 tick 推进内在生命/欲望/活动，用户交互随时插入打断。

## 3. 事件系统

### 3.1 单一事件流 + 路由

不区分"输入/输出"二分。所有事件同构，只在 `source` 上区分外部/内部。

**Event 结构**：

```yaml
Event:
  id            # 唯一
  timestamp     # 时间
  source        # 外部(用户/时钟/观察) | 内部(模块)
  type          # 语义类型（= EventType 枚举成员）
  content       # 内容
  correlation_id  # 溯源链：由谁引发
  # target 由 ROUTING[type] 派生，不存字段
```

### 3.2 路由表（纯数据，可单测）

ROUTING 的 key 即 `Event.type`（EventType 枚举成员，snake_case），值是**内部模块消费者**列表（空 = 仅广播到前端，无内部消费者）。SSE 广播全部事件给前端，REST 只做初始快照/历史查询/导出。

```python
ROUTING = {
    EventType.USER_MESSAGE:        ["expression"],
    EventType.OBSERVATION_STATE:   ["inner_life", "desire"],   # 情感 + 互动欲加压
    EventType.DESIRE_GENERATED:    ["activity"],
    EventType.DESIRE_SATISFIED:    ["inner_life"],
    EventType.DESIRE_EXPIRED:      [],
    EventType.ACTIVITY_START:      [],
    EventType.ACTIVITY_END:        ["desire", "inner_life", "memory"],  # 满足+情感+活动记忆
    EventType.ACTIVITY_INTERRUPTED: [],
    EventType.SPEAK:               [],
    EventType.ASK:                 [],
    EventType.THINK:               [],
    EventType.MUTTER:              [],
    EventType.INITIATE_CHAT:       [],
    EventType.EMOTION_UPDATE:      [],
    EventType.REFLECTION:          ["inner_life"],   # 协调器，内部调 memory/desire
    EventType.MEMORY_CREATED:      [],
    EventType.MEMORY_PROMOTED:     [],
}
```

**自消费澄清**：`memory_created` / `memory_promoted` / `desire_expired` 是模块**自己已同步完成动作后**发出的通知——路由为空（无内部消费者），仅用于溯源 + 广播前端，不触发二次处理。`desire_satisfied` 例外：除通知外还路由到 `inner_life` 做满足情感回写——这是欲望→内在生命的**唯一耦合点**（走事件而非 Facade 直接互调，避免成环）。

`clock_tick` 特殊：按 `content.tick_type` 走 TICK_ROUTING 二次路由（1 个 tick_type → 1 个消费者，非广播）：

```python
TICK_ROUTING = {
    TickType.SCHEDULE_BLOCK_START: ["activity"],
    TickType.DESIRE_EVAL:          ["desire"],
    TickType.MUTTER_CHECK:         ["expression"],
    TickType.INITIATE_CHAT_CHECK:  ["expression"],
}
```

**外部输入只有三种**：用户消息、时钟 tick、观察状态。其余均为模块间内部事件。

### 3.3 抢占语义（活动软状态可恢复）

- 活动有进度（读书读到第 Y 段）
- 搭话/用户消息到来 → 活动暂停、保存进度 → 搭话/回复执行
- 打断结束：仍在同一日程块内 → 恢复；否则标记"未完成"，进度保留可续

### 3.4 溯源链

`correlation_id` 贯穿因果链（用户消息 → 回复 → 记忆 → 反思），前端按 `correlation_id` 分组、沿时间戳排序溯源。

## 4. 内在生命系统

### 4.1 静态人格（YAML + MD，几乎不变）

基本故事、说话方式、口头禅、世界观。用途：拼 prompt 注入。见 `docs/canon.md`（摘要 + 初始数值 + 原始 prompt 文件指针）。

### 4.2 动态数值（1-10，会变）

| 层 | 内容 | 变化来源 | 速度 |
|---|---|---|---|
| 情感 | valence + arousal + 情绪标签 | 输出事件 | 快，衰减回基线 |
| 性格 | Big Five 五维度 | 只被反思 | 慢漂移 |
| 三观 | 4 维度（草案，见下） | 只被反思 | 最慢 |
| 精力 | 数值 + 5 档状态 | 活动消费/恢复 | 中 |

**性格（Big Five 简版）**：开放性 / 尽责性 / 外向性 / 宜人性 / 神经质，各 1-10，初始值见 `../canon.md`。

**三观（4 维度，初始值见 `../canon.md`）**：

| 维度 | 0 端 | 10 端 |
|---|---|---|
| 对人类的态度 | 疏离 | 向往 |
| 对 AI 身份的接纳 | 挣扎 | 坦然 |
| 利他↔利己 | 利己 | 利他 |
| 乐观↔悲观 | 悲观 | 乐观 |

**情感**：valence ∈ [-1,1]、arousal ∈ [0,1]，加离散表情标签（8 档，见 tech-ref §1 EmotionCategory：平静/开心/难过/生气/担忧/害羞 + 困倦/思考两个覆盖）。输出事件 = 坐标偏移，随时间衰减回基线。表情选择优先级：困倦 > 思考 > 情绪。

### 4.3 自我叙事（文本化的自我，反思维护）

```yaml
self_narrative:
  identity: "我是模仿女主人公创造的 AI，希望能成为人类"
  story: [关键经历片段]
  self_view: { 优势, 弱点, 困惑 }
  becoming: [近期自我认知变化]
```

与静态人格/三观互补：静态人格=设定，三观=数值化自我，自我叙事=文本化自我。

### 4.4 当前状态

上述数值 + 当前日程块 + 当前欲望，合成只读快照，缓存内存，供表达拼 prompt。

### 4.5 持久化

- 性格 / 三观 / 精力 / 自我叙事 → SQLite
- 情感 → 内存（易变），可定期快照，重启后从基线重启

## 5. 表达系统

### 5.1 回复流程

```
事件 → 调用工具选择 → 拼装 prompt → think + speak + ask → 记录 message → 生成场景化记忆
```

**拼装 prompt 三步**：

1. **回溯上下文**：边回溯边检测，命中"时间隔太久 / 快通道信息 / 十分不相关"或满 20 条即停
2. **搜索记忆**：第一遍关键词 → 第二遍向量 → 第三遍联想（networkx）
3. **获取当前状态**：读内在生命快照

### 5.2 快慢通道

- **判定**：启发式规则（纯函数）——消息长度、是否含问句、情感词、当前精力/情感、距上次慢通道时间，加权归一化得分(0-1) 与 `slow_threshold` 比较，超阈值走慢通道
- **快通道**：只思考一轮，不检索记忆，不生成场景化记忆
- **慢通道**：完整三步拼装，最多思考三轮，生成场景化记忆

**轮数重置**：慢通道每轮结束若发 `ask` → 进入等待用户；用户回答后轮数重置；不回答则超时记"用户未回答"，回合结束。

### 5.3 场景化记忆

- 只慢通道生成
- **一次 LLM 调用产出三样**：记忆内容 + 标签 + 总结；矛盾检测是**门控的独立 LLM 调用**——embedding 召回 top-K 候选、相似度过阈值才 +1 调用（单任务判矛盾，准确率优先），无候选则 0 调用
- 是尼克斯视角的叙事（"用户和我说了 xx，我觉得 xx，所以说了 xx"）

### 5.4 碎碎念

- 50 条固定模板，时钟/日程驱动，空闲时随机触发

### 5.5 搭话（主动）

- **跨活动即时行为**，不占日程块，可打断任意活动
- 触发（纯函数）：互动欲队列非空（已有未消费的互动欲望）+ 用户在线 + 不忙 + 精力够 + 距上次搭话 ≥ 间隔
- 走快通道，基于队列里的互动欲望 + 观察状态 + 记忆
- 用户回应 → 转正常回复；不回应 → 记"被忽略"→ 互动欲值回增

## 6. 记忆系统

### 6.1 结构

```yaml
memory:
  content     # 内容
  tag         # 标签（user = 用户画像）
  summary     # 总结
  freshness   # 新鲜度
  type        # 短期 | 长期
  edges       # 联想边（networkx）
```

### 6.2 生命周期

- **创建**：打标签 → 建联想边 → 进短期队列 → 检测矛盾（有则触发反思）
- **升级**：短期 --"实际用进回复 3 次"--> 长期（"想起"精确定义：检索命中 **且** 拼进 prompt 实际影响输出；检索到但没用上不算）
- **短期遗忘**：容量上限 + 新鲜度淘汰（满了挤掉最新鲜度最低的）
- **长期**：不消失，只新鲜度下降（检索时排后）

### 6.3 检索三层

1. 关键词搜索（SQLite FTS/LIKE）
2. 向量匹配（本地 embedding → 余弦相似度）
3. 联想（networkx 沿边扩散）

三层在 `MemoryFacade.search(query)` 内部顺序执行并去重合并，对外只返回一份 `list[Memory]`；`SearchMode` 是内部层标签（用于单层测试/来源标记），不暴露在公开签名。

### 6.4 用户画像

`tag='user'` 的长期记忆，带 `aspect` 字段（相处模式/身份背景/常聊话题/情绪敏感点），**一个记忆可挂多个 aspect**（如"和父亲关系不好"同时是身份背景 + 情绪敏感点）。产生：场景化记忆顺带打标 + 反思聚合。

## 7. 欲望系统

### 7.1 短期 vs 长期

| | 短期欲望 | 长期欲望（野心） |
|---|---|---|
| 生命周期 | 产生→满足→消退 | 持续存在，缓慢演化 |
| 来源 | 值机制（活动/对话/长期加压） | 人设卡初始 + 反思孵化（≤5） |
| 满足 | 一次活动 | 被短期部分满足，强度微降不归零 |

### 7.2 短期欲望全周期（压力-释放）

```
[活动/对话/长期欲望] → 给类型加"值"（值缓慢衰减）→ 达峰值
  → 拼装上下文(主题种子+情境) → LLM 生成 {描述, 可量化目标} → 值重置
  → 入该类型 FIFO 队列 → 被活动系统消费 → 规则判定可量化目标
      ├ 达成 → 满足信号 → 出队 + 回写(权重/长期进度/情感)
      └ 未达成 → 插回队首，重试计数+1；重试>3 → 放弃，值回增，可选触发反思
  → 过期/队列满淘汰 → 值回增（压力回灌）
  → 每次满足/抑制后更新表达权重 + 抑制阈值
```

**情感回写**：欲望达成时 `DesireFacade.satisfy()` 发布 `desire_satisfied` 事件，由 `inner_life` 消费更新情感（正偏移）——互动欲（对话满足）没有 `ACTIVITY_END`，靠这条路由兜底保证情感不丢；活动欲则 `ACTIVITY_END → inner_life`（完成感）与 `desire_satisfied → inner_life`（满足感）两路都有。

**四种短期欲望**：互动 / 探索 / 创造 / 休息。

### 7.3 主题种子

长期欲望周期性给对应类型"加压 + 主题种子"。种子来源：

1. 长期欲望自带子主题池（YAML，按"没做过/新鲜度最低"取）
2. 记忆系统未完成话题优先

### 7.4 可量化目标

生成欲望时 LLM 同轮输出**规则可判定的完成判据**：

```yaml
desire: "查中世纪骑士团"
goal: { action: read, count: 3, topic: 骑士团 }
```

完成判定是纯函数，不额外调 LLM。

### 7.5 长期欲望入口

- 初始集来自人设卡（见 `../canon.md`）：理解人类 / 理解小说里的自己 / 陪伴并理解用户（共 3 个）
- **反思是唯一能新增/强化长期欲望的入口**
- 消退不消失；短期满足时回写长期"进度 + 迫切度微降"

## 8. 活动系统

### 8.1 日程块

固定时间网格，每小时一块（YAML 可配）。**日程块是 grid 派生的临时概念，不建表持久化**：`Activity.schedule_block_id` 存时间标签（如 `"14:00"`），非外键；空日程块无 `Activity` 记录，前端时间线按 grid 自行渲染空槽。

### 8.2 六种日程块活动

| 活动 | 满足 | LLM 成本 |
|---|---|---|
| 读书 | 探索欲（读本地书库） | 1 次（总结+笔记） |
| 自由探索 | 探索欲（工具链探索=跨域行为链） | 高（多步，LangGraph） |
| 创作 | 创造欲（写笔记） | 1 次 |
| 观察用户 | 情报收集 + 互动欲加压 | 0 |
| 发呆(反思) | 内在生命维护 | 1 次 |
| 休息 | 休息欲（恢复精力） | 0 |

> 「读本地书库」已落地（MVP）：读书读的是用户上传的资料（`material` 表 + `MaterialStore`），分块读、标进度，探索欲触发时读最近未读完的那本，读完自动换下一本；无书可读时转自由探索——绝不凭空编造（实现见 specs/14-activity）。

### 8.3 跨活动即时行为

- **搭话**、**碎碎念**：不占日程块，可打断任意活动（见 §5.5、§5.4）

### 8.4 精力值

数值 0-100，五档映射：

| 档 | 范围 |
|---|---|
| 精神满满 | 80-100 |
| 还行 | 60-79 |
| 有点累 | 40-59 |
| 疲惫 | 20-39 |
| 提不起精神 | 0-19 |

消耗：读书 -20 / 创作 -25 / 自由探索 -30 / 观察 -10 / 发呆 +10 / 休息 +30，夜间自动恢复。

### 8.5 观察用户

- 默认：键盘/鼠标活跃度 + 前台窗口标题 → 判断在线/离开/忙碌
- 屏幕视觉（截屏+视觉模型）为用户**手动开启**（opt-in）

### 8.6 跨域行为链（自由探索的 LangGraph 实现，MVP 就做）

"好奇深海鱼 → 搜索 → 下载 → 打开 → 边读边写笔记 → 想到用户聊过 → 翻旧聊天 → 关联 → 日记记一笔"的完整闭环。触发门槛：探索欲峰值 + 精力充足 + 频率上限。

> MVP 只实现「搜索 → 读 → 写笔记」+ 活动结果落记忆（不翻旧聊天）；「翻旧聊天 → 关联」（联想记忆）仍留 V2。

## 9. eval 体系

### 9.1 三层（成本分层）

| 层 | 手段 | 覆盖 |
|---|---|---|
| 结构校验 | 纯函数：格式解析/字段/数值合法 | 100% 全量 |
| 规则评分 | 纯函数/启发式：OOC 规则/重复度/长度/一致性 | 100% 全量 |
| LLM-judge | 语义质量 1-5 分 | 抽样（每 N 条或可疑时） |

### 9.2 OOC 三档

1. 关键词/语癖规则（白名单+黑名单）
2. embedding 相似度（对比尼克斯基准语料）
3. LLM-judge（喂人格设定卡）

### 9.3 报告（可展示 + 溯源）

```yaml
eval_report:
  output_id, module, type
  scores: { format: 1.0, ooc: 0.8, relevance: 4.0 }
  token_usage: { input, output }
  correlation_id
```

eval 结果**纯记录 + 可视化**，不自动反馈修正。

## 10. 数据模型总览

| 数据 | 存储 | 说明 |
|---|---|---|
| 静态人格 | YAML/MD 文件 | canon |
| 情感 | 内存 | valence/arousal/标签，可定期快照 |
| 性格 | SQLite | Big Five 5 列 |
| 三观 | SQLite | 4 列（可扩展） |
| 精力 | SQLite | 数值 + 状态 |
| 自我叙事 | SQLite `self_narrative` | 反思维护 |
| 记忆 | SQLite `memory` + networkx(内存) | 短期/长期，tag 含 user |
| 短期欲望 | SQLite `desire` | 队列 + 值 |
| 长期欲望 | SQLite `long_term_desire` | ≤5 |
| 活动 | SQLite `activity` | 进度/状态 |
