# Nyx Agent 产品与架构愿景

> 本文件只保留产品定位、长期设计原则和文档边界。
> 已实现功能的契约以 `docs/specs/` 为准，当前源码事实见 `docs/facts/`；
> 本文件不重复定义 API、数据表、事件路由、状态机、阈值或实现步骤。

## 1. 产品定位

Nyx Agent 是住在用户电脑里的桌面 AI 同伴。她会观察用户状态、记住互动、
产生自己的动机，并在合适的时候主动表达。她明确知道自己是 AI，并希望逐渐理解
人类、理解自己，也理解与用户共同生活的关系。

项目同时服务于两个目标：

- 提供一个有持续状态和主动性的本地陪伴体验；
- 作为一个可审查、可测试、可演进的 Python/React 工程作品。

## 2. 长期设计原则

1. **状态持续而非一次性生成**：记忆、欲望、内在生命和活动共同构成连续的行为背景。
2. **快慢分层**：低成本路径保证日常响应，高成本路径负责记忆检索、思考和沉淀。
3. **事件可追溯**：跨模块行为通过事件建立因果链，并以 `correlation_id` 支持回溯。
4. **本地优先**：用户数据默认留在本机；网络访问只服务于明确启用的模型、搜索或抓取能力。
5. **失败可恢复**：外部调用、事件消费和可续活动都应有明确的失败、重试或恢复边界。
6. **契约单一入口**：每个领域只有一份完整 spec；事实摘要只服务于快速导航。

## 3. 系统形态

系统由本地 Python 服务、React/TypeScript 前端和 Tauri 壳组成。后端以组合根装配
各 Facade、SQLite、LLM 客户端和事件总线；前端通过 REST 获取快照和执行操作，通过
SSE 接收实时事件。

业务领域包括：

| 领域 | 职责 | 完整契约 |
|---|---|---|
| 事件与底层建设 | 类型、配置、LLM、数据库、总线和运行时边界 | `docs/specs/01-types.md`、`02-config.md`、`03-llm.md`、`04-module-bus-system.md` |
| 记忆 | 写入、去重、召回、联想和长期沉淀 | `docs/specs/06-memory-system.md` |
| 欲望 | 压力、产生、领取、消费、满足和淘汰 | `docs/specs/07-desire.md` |
| 内在生命 | 情感、精力、慢变量、自我叙事和反思 | `docs/specs/08-inner-life.md` |
| 活动 | 排期、执行、打断、恢复和活动结果 | `docs/specs/09-activity.md` |
| 表达 | 回复、提问、主动搭话、碎碎念和等待 | `docs/specs/11-expression.md` |
| 阅读 | 书库、进度、陪读冲动、笔记和整合 | `docs/specs/12-reading-system.md` |

工具和评估是横切能力，分别由 `docs/specs/05-tools.md` 和
`docs/specs/10-eval.md` 约束。

## 4. 行为模型

Nyx 的持续行为由几类状态共同驱动：

- **记忆**提供过去经验和用户画像；
- **欲望**提供当前动机；
- **内在生命**提供情绪、精力、性格、三观和自我叙事；
- **活动**把动机转成可执行的行动；
- **表达**把当前状态转成对用户可见的语言；
- **事件总线**连接跨模块因果和前端观测。

这些模块不是独立的聊天插件，而是一个持续运行的本地状态系统。具体读写边界、
事务语义和失败策略由对应完整 spec 定义。
