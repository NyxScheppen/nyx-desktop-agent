# 开发约定

适用于整个仓库。系统与操作入口见 [文档入口](README.md)，具体实现以当前源码为准。

## 工作流程

1. 先只读调查相关代码、配置、调用方、消费者和已有验证；按需读对应 facts，不必通读全部文档。
2. 新功能、行为变更、bug 修复以及文档落盘修改，先提交最小计划供用户明确审核，再实施。计划说明需求、假设、影响路径、预计文件和验证方法；范围或关键方案变化时重新审核。已获批准的范围继续执行。
3. 只改解决需求所需的内容，遵循相邻风格；复用已有实现，不为单次使用建立抽象，不添加未经请求的配置或扩展层。清理本轮造成的未使用代码。
4. 完成后按影响范围验证，说明实际结果和未覆盖项；提交前审查差异，按需查 [经验教训](LessonsLearned.md)。只沉淀新的可复用问题，不要求每次追加记录。

修改持久化或跨模块对象时，在调查与计划中核对它的写入口、全部消费者、状态变化，以及相关的失败、部分完成、乱序、重放和删除路径。不要求为此维护单独的规格书或重复审计表。

## 代码与数据

- Python 使用完整类型注解；I/O 与异步入口用 `async def`，纯计算保持同步。公开方法解释必要的原因和边界。
- TypeScript 保持 strict；React 组件使用现有命名与组织方式，全局状态用现有 Zustand stores，事件流沿用 SSE 接线。
- 模型调用复用统一客户端。核心失败应可观察、可恢复；旁路可降级，但不能吞掉取消、伪造成功或遮蔽核心提交错误。
- 不增加未经需求支持的架构层；不要为了方便跨层直接改写其他系统的存储。
- API Key、根凭证、设备令牌、数据库 URL 和运行数据不写入源码或提交；密钥经环境变量或已授权 Secret 来源注入。
- 数据只保存功能必需部分。默认本地运行；用户明确选择托管时才存入其指定项目。LLM 请求走 HTTPS，联网与 OneBot 按用户配置启用，真实外发遵守授权范围。
- 公网继续遵守单用户 HTTPS/Bearer/设备配对边界；具体部署按 [线上操作](deployment.md)。

## 验证原则

- 以路径分析和实际行为评测为主：沿触发入口、受理、状态变化、事件、消费者、持久结果和界面检查完整路径；只补与本次风险相关的失败与恢复场景。
- 改 prompt、策略或角色行为时用真实模型评测效果；mock 主要证明流程接通，不能证明模型理解或回答质量。
- 优先复用已有回归与 E2E 驱动。单元测试非必要不增加；仅在关键纯逻辑或稳定回归用例确有价值时补充，不设每方法/API 配额，不写复制实现或声明的测试。
- 保留现有测试，按影响范围选用；不维护测试文件索引和数量快照。不要为凑覆盖率机械新增单测。
- 验证生成的探针、日志、截图、报告、覆盖数据和临时数据库使用临时目录，成功或失败结束后自动清理，不在仓库保留 `artifacts/`。需要归档时仅记录必要结论；正式构建制品按打包流程保留。
- 未执行、缺环境或失败要如实标记，不能用历史通过记录代替本次结果。纯文档修改检查链接、引用和差异即可。

静态检查按涉及范围执行：

```powershell
uv sync --locked --extra dev
uv run --no-sync python -m ruff check nyx/ tests/ scripts/
uv run --no-sync python -m pyright nyx/ tests/ scripts/
```

```powershell
Push-Location frontend
npm ci
npm run build
Pop-Location
```

路径回归、页面验收与真实模型评测方法见 [评测文档](eval/README.md)。桌面构建见 [本地操作](operations.md)；发布时执行 [线上操作](deployment.md) 的完整检查。

## 文档与交流

- 内部实现改动不要求更新文档；只有职责、关键行为边界、操作方式或设计方向变化时才更新对应一处资料。
- 不要求先写 spec，不复制代码签名、DDL、阈值或测试断言。facts 与代码冲突时核对代码并修正摘要；设计思路不参与系统事实判断。
- 移动或删除文档后检查内部相对链接、引用方和源码注释。`AGENTS.md` 与 `CLAUDE.md` 的共享入口同步。
- 明确假设和取舍，有疑问先调查，不凭空扩展需求。编码交流可扮演狐狸娘，口头禅“小狐狸我呀”。
