# 路径验证与行为评测

以完整路径和实际行为为主，单元测试非必要不增加。已有测试按影响范围复用，不维护逐测试文件索引或数量快照。

## 选择验证方式

| 改动 | 验证重点 |
|---|---|
| API、事件、存储或跨系统对象 | 从入口追到持久结果和消费者，检查受理、完成、失败、重放与删除的相关路径 |
| prompt、规划、反思或角色表达 | 真实模型是否理解要求、使用了什么证据、实际做了什么、结果是否符合预期 |
| 前端与角色切换 | 真实页面中的输入、等待、迟到回包、刷新、切换和 SSE 恢复 |
| PostgreSQL、部署或桌面打包 | 对应真实数据库、HTTPS 或冻结制品验证，不能只用替身或源码检查代替 |
| 纯文档 | 相对链接、残留引用、规则一致性与差异检查 |

静态检查见 [开发约定](../development.md)，构建见 [本地操作](../operations.md)，发布的完整检查见 [线上操作](../deployment.md)。

## 复用已有驱动

在仓库根运行全部隔离 E2E：

```powershell
uv run --no-sync python scripts/run_e2e.py --timeout 600
```

统一入口会发现现有成功驱动并隔离认证、数据库部署变量，不调用真实 LLM/QQ。需要定向验证时，根据本轮路径在 `scripts/e2e/` 中选择相关驱动，先读其环境要求，不复制维护一份文件清单。

已有后端与前端回归可按需运行：

```powershell
uv run --no-sync python -m pytest -q
Push-Location frontend
npm test -- --run
Pop-Location
```

直接运行 pytest 可能受本机 `.env` 的认证或 OneBot 配置影响；完整发布检查使用[隔离配置入口](../deployment.md#2-代码变更先完成本地验证)，它也会采集 E2E 子进程覆盖率。不能把环境导致的失败写成通过。覆盖率不证明行为质量，也不构成机械补单测的理由。

## 真实模型效果

在隔离宿主、临时数据及受限工具中运行，记录模型、输入、预期、实际动作和最终回复。固定工具或初始计划时明确说明受控部分；不把单次通过说成稳定成功率。

| 场景 | 观察目标 |
|---|---|
| 简单问候或无实时资料的问题 | 不强行规划，不编造查到的内容 |
| 查两份资料的关系 | 计划服务任务，结论可追溯到实际读取的材料 |
| 工具空结果或失败 | 正确继续、换路或停止，回复忠实于实际执行 |
| 同主题多次纠错 | 反馈被记录，后续经验与反思结果可观察，明确区分用户提示与自主变化 |
| 连续补充、撤回或改日期 | 保留未撤销条件，停止尚未执行的旧动作，如实保留已执行动作 |
| 批注与引用 | 区分用户观点、外部资料、历史与模型推测，刷新后反馈仍存在 |

每项记录 `PASS / FAIL / NOT_RUN`、存储后端、真实或模拟依赖、判定证据与限制。实际页面、真实模型、真实数据库分别报告；只有需要保留的发布或效果结论才写入历史记录，不要求每次代码修改追加。

## 对话历史 RAG 定量评测

在仓库根运行：

```powershell
uv run --no-sync python -m scripts.evaluate_memory_rag --repeats 3
uv run --no-sync python -m scripts.evaluate_memory_rag --answers --repeats 3
```

驱动与固定标注分别在 [evaluate_memory_rag.py](../../scripts/evaluate_memory_rag.py) 和 [rag_cases.py](../../scripts/rag_cases.py)。默认使用真实本地 ONNX，对比关键词与混合检索；`--answers` 额外读取本地模型配置，调用真实最终回复模型。数据库、宿主状态和故障探针全部在自动清理的临时目录中，忽略部署数据库变量；完整 JSON 输出到 stdout，进度到 stderr。未达到门槛时退出码为 1。需要留存原始报告时也使用临时目录。

语料包含 20 段合成对话、24 条独立标注查询：17 条正例、7 条负例，其中 16 条安排最终回答评测。覆盖改写、长对话前部与中部、相近干扰、否定纠正、迟到历史事实、冷归档、角色隔离、无证据、引文归属和提示注入。每个回答使用新宿主，防止前一条回答污染后续样本。

指标以去重来源 ID 的 Top 5 为单位：Recall、固定分母 Precision、MRR、二值 nDCG 只在正例上平均；证据召回额外要求返回片段包含全部标注信息，否定事实还核对极性。负例空结果率单列，召回相关材料不等于材料能支持回答。当前正例各有一个正确来源，故 Precision@5 的理论上限是 20%。延迟包含查询编码、索引同步和追踪写入，不包含入库、精确对照诊断和模型生成；每条查询预热一次后采样。

门槛在首轮测量前固定：混合检索 Recall@5 与证据召回均至少 90%，MRR@5 至少 0.80，返回范围及生命周期检查全部有效；启用回答时所有回答用例也必须通过。回答核对实际发布正文、关键答案、未知说明、禁止模式、最终 prompt 依据及适用的来源注入轨迹。服务错误记为 `ERROR`，停止后续模型请求并记为 `NOT_RUN`，不能当成回答错误率或通过；默认未运行回答时该门槛为 null。

限制：事实人工种入，不测自动提取准确率；工具选择和其他生命周期模型受控，质量检索使用真实 ONNX。回答从表达门面直接触发，HTTP 受理路径另由既有对话 E2E 验证。角色隔离核对独立角色存储，未代替实际页面切换；回答规则不是完整语义忠实度裁判，仍需阅读实际正文。合成语料分数不代表生产准确率。
