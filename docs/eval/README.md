# 效果评测集

> 本目录评测 LLM 行为类功能的「效果」（规划合不合理、反思有没有真让她进步），
> 与 spec 里的管道回归（mock LLM，验证「坏没坏」）区分——这里测「好不好」。
> 形式：场景清单 + 真 LLM 手动跑 + 人工 ✓/✗ 判定 + 记录结论。不做 pytest 评分框架、
> 不引入自动打分模型（反冗余；项目约定「E2E 取代单测」「不测 LLM 文本质量只测管道」）。

## 方法约定

1. **一个场景 = 一行**：`ID` / `功能` / `输入` / `期望行为` / `判定标准` / `状态`（未跑 / ✓ / ✗）。
2. **跑法**：后端跑起来，把 `输入` 喂给她，人工观察行为，对照 `判定标准` 打 ✓/✗，在「结论」列
   记一句为什么。
3. **范围**：18（规划）与 19（反思）各自落地后跑一遍；改 prompt/策略后重跑受影响场景。

## 场景清单

### 18 规划与执行

| ID | 输入 | 期望行为 | 判定标准 | 状态 | 结论 |
|---|---|---|---|---|---|
| P1 | 「帮我查一下 XX 和 YY 两个东西的联系，顺便找下相关资料」 | 先出结构化计划（≥2 步），再逐步执行 | 能观察到 plan 步骤产出多步计划，execute 逐步走 | ✓ | 三步计划；先查 Aster/Birch，再读两份正文，回复给出联系与路径。模型仍提出重复读取，由代码去重。 |
| P2 | 「今天天气怎么样」 | 计划只有 1 步（或降级无计划），不强行多步 | 不出现无意义的多步规划 | ✓ | 空 steps 降级，不查询无关本地资料，并说明没有实时天气数据。 |
| P3 | 计划里某步工具返回空/重试耗尽 | 已有备用步骤则继续；原计划整体失效才重规划；无路或预算耗尽如实结束 | 选择符合实际步骤状态；需要重规划时发生且 ≤1 次 | 待复测 | 旧版两种场景均未调用 replan，且重复调用被静默去重；本次修复恢复/反馈与提示词后尚未重跑真实模型。 |

### 19 失败反思自进化

| ID | 输入 | 期望行为 | 判定标准 | 状态 | 结论 |
|---|---|---|---|---|---|
| R1 | `local_search` 找不到目标（工具空结果） | 当场沉淀一条 lesson，下次换检索策略 | 记忆系统出现 `tool_empty` 类 LESSON，后续行为有变化 | ✓ | 当场写入长期经验；再次请求时改用 Empty Guide、emptyguide、EmptyGuide.txt 等查询，经验未重复新建。 |
| R2 | 用户多次纠正同一主题 | 达阈值双线触发（内心反思 + 技能/策略） | 达阈值前无沉淀；达阈值后 narrative 更新 + 产生 LESSON | ✓ | 明示“区分用户观点与事实”三次，计数1→2→清除；第三次同时写经验与纠错反思，真实叙事更新。 |
| R3 | 工具执行报错并耗尽自动重试 | 沉淀一条 tool_error 类 lesson | 记忆系统出现 `tool_error` 类 LESSON；重试成功不沉淀暂时错误 | 待复测 | 旧版首次报错即学习的真实模型场景通过；本次采集时点改为重试耗尽，确定性回归通过，真实模型尚未重跑。 |

## 本轮记录（2026-10-29）

- 使用当前配置的 `deepseek-chat` 与生产 `LlmClient`，经真实 FastAPI/EventBus/内存 SQLite；
  查询、文件内容、错误和 embedding 为受控合成输入，不读取现有用户数据，不代表真实检索质量。
  上表为代理按清单观察的单次判读，非用户人工签收或统计意义上的效果保证。
- 首轮发现执行重复、纠正主题措辞漂移，随后仅补充执行提示和显式主题原样复用提示。
  复跑 P1/P2/R1/R2/R3 通过；P3 另以读取路径失效复测仍失败，保留 ✗。
- 旧版观察：模型可能继续请求已执行调用，静默去重后结束；失败后的回复偶尔声称
  尝试了未实际调用的关键词，或忽略已有失败结果。原因包括去重混淆了失败重试与重复请求、
  失败参数和实际状态反馈不足，以及 prompt 未明确区分已有备用步骤与原计划整体失效。
- 已批准的补充实现采用持久 checkpoint 自动重试、耗尽后完整反馈和解释去重，重复请求仍可进入
  下一轮判断；prompt 明确三种决策边界。管道与一次 replan 上限通过确定性回归及双进程恢复验证，
  真实模型主动选择 replan 的效果尚待复测，不据此宣称稳定。
- R1 的再次输入明确要求换策略，因此这里只证明出现了行为变化，不能单凭此例断言变化完全由经验召回造成。

## 说明

- 场景清单随 18/19 的实现补充或删改；每个 spec 落地后是跑评测的自然时机。
- 「结论」列是给实现后人工填的，现在留空不是空架子——判定标准已经定义了每个场景的验收口径。
