# 效果评测集

> 本目录评测 LLM 行为类功能的「效果」（规划合不合理、反思有没有真让她进步），
> 与 spec 里的管道回归（mock LLM，验证「坏没坏」）区分——这里测「好不好」。
> 形式：场景清单 + 真 LLM 手动跑 + 人工 ✓/✗ 判定 + 记录结论。不做 pytest 评分框架、
> 不引入自动打分模型（反冗余；项目约定「E2E 取代单测」「不测 LLM 文本质量只测管道」）。

## 方法约定

阶段2OneBot（2026-10-30）只增加传输，不修改LLM prompt/策略。当前验收使用本地模拟OneBot WS、
脚本化LLM与真实SQLite/宿主/表达链，验证私聊入向、重复上报、出向echo、断线续发和角色卸载恢复；
不代表模型文本质量验收。用户随后已确认真实QQ往返；本次内心话扩展仍以自动化模拟WS验收，
验证THINK独立消息的“💭 内心话”前缀、先于正文及恢复不重发，手机端实际展示待用户体验确认。
配置步骤见21-onebot-transport契约文末。
本次内心话扩展最终全量1364 passed / 1 skipped（190.91s）、Ruff/Pyright零错误；
阶段2时已复跑阶段1脚本化HTTP/SSE场景FAST/P1–P3/R1–R3，共40帧通过；本次未新增真实模型调用。

阶段3（2026-10-30）不改变LLM/领域语义；验收使用临时 SQLite、真实 FastAPI/EventBus、Caddy 内部 CA 和 Chrome。通过同源登录、REST/SSE/角色图片 Bearer、Origin/预检、ready 隔离、1005 条提交序事件的双 reader 断点续传与资源回收。前端 UI 登录及连接后的应用页面均实际打开；没有域名、公网证书或移动端真实部署验收。

1. **一个场景 = 一行**：`ID` / `功能` / `输入` / `期望行为` / `判定标准` / `状态`（未跑 / ✓ / ✗）。
2. **跑法**：后端跑起来，把 `输入` 喂给她，人工观察行为，对照 `判定标准` 打 ✓/✗，在「结论」列
   记一句为什么。
3. **范围**：18（规划）与 19（反思）各自落地后跑一遍；改 prompt/策略后重跑受影响场景。

## 本轮记录（2026-10-29）

- 使用当前配置的 `deepseek-chat` 与生产 `LlmClient`，经真实 FastAPI/EventBus/内存 SQLite；
  查询、文件内容、错误和 embedding 为受控合成输入，不读取现有用户数据，不代表真实检索质量。
  上表为代理按清单观察的单次判读，非用户人工签收或统计意义上的效果保证。
- 首轮发现执行重复、纠正主题措辞漂移，随后仅补充执行提示和显式主题原样复用提示。
  复跑 P1/P2/R1/R2/R3 通过；当时 P3 的路径失效场景未触发 replan，后续发现初始计划
  已含备用搜索步骤，单凭 replan=0 不足以判失败。
- 旧版观察：模型可能继续请求已执行调用，静默去重后结束；失败后的回复偶尔声称
  尝试了未实际调用的关键词，或忽略已有失败结果。原因包括去重混淆了失败重试与重复请求、
  失败参数和实际状态反馈不足，以及 prompt 未明确区分已有备用步骤与原计划整体失效。
- 已批准的补充实现采用持久 checkpoint 自动重试、耗尽后完整反馈和解释去重，重复请求仍可进入
  下一轮判断；prompt 明确三种决策边界。管道与一次 replan 上限通过确定性回归及双进程恢复验证，
  最新 P3 重新验收使用原输入3次、无路输入2次及无备用固定计划5次。
- 无备用旧计划修复前仅2/3发出 replan，其中一次延迟；模型会将临时查找新版本资料
  当作原计划备用路径。现在耗尽后先输出 continue/replan/stop；继续须指向原计划步骤，
  重规划完成后反馈已用/剩余次数，避免把旧决策重复当作待办。
- 最终5个无备用样本均在三次读取失败后先选择 replan、生成新计划，再实际读取 v2；
  每个仅一次重规划，v2 实际读取一次，最终明确未实际部署或探测。已有备用的3个样本均
  选择 continue 并读取替代文件；2个全空样本不重规划、不编造内容。10轮事件交付均成功。
  模型为 `deepseek-chat`、temperature=0.8。无备用场景固定初始计划，不能称为全流程真实规划；
  5/5是本轮观察值，不是统计意义的稳定成功率。
  验收结论保留于本文；临时驱动、完整轨迹与合成测试库已在验收后清理。
- R1 的再次输入明确要求换策略，因此这里只证明出现了行为变化，不能单凭此例断言变化完全由经验召回造成。

## 真实模型讨论与批注复测（2026-10-30）

  因累计外部调用超过单次驱动等待窗口而中止；拆成新鲜数据库后强制讨论完成，真实模型实际执行
  3 轮工具判断并最终回复。联网返回空来源时，回复明确说明无法核实，没有把空结果说成已找到来源。
- 受控知识来源场景通过真实 `deep_research`：两条合成网页进入研究报告，最终回复带两条真实执行来源，

  按生产契约改为正文字符串后重跑通过。该结果只证明管道和引用纪律在受控来源下工作，不代表外网来源质量。

  `correction_topic`，同主题计数无法达到阈值；实现随后增加显式 `【主题】` 标签优先作为聚类键，
  并补 SQLite 回归。修复后 `【来源不确定性】` 三次批注稳定聚类，第三次触发真实 reflection、
  `REFLECTION_DONE`、LESSON 和叙事更新。模型仍可能在抽取 JSON 中输出不同主题，但显式标签不会被改写。
- 2026-10-31 完成批注前端真实浏览器验收：从现有历史中选中已结束 `SPEAK`，填写并发送批注，
