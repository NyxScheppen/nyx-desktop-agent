# 活动系统基本事实

> 记录职责与关键边界；调度顺序、状态机、阈值和 checkpoint 结构查源码。

## 职责与行为

- 把欲望、用户委派和空闲安排转成读书、创作、自由探索、观察、反思或休息。
- 活动由后台任务执行，事件处理不等待整段模型或阅读流程；同一角色只运行一项活动。
- 启动时一并领取来源、保存活动并产生开始事件；结束、失败和打断也要与关联任务、欲望保持一致。
- 用户消息可请求打断活动；读书、创作和自由探索支持保存进度后续接。旧执行者尚未停止时不能另开重叠活动。
- 重启与失败恢复会调和没有执行者的运行态；不能把所有未完成工作直接当成完成。
- EPUB 从阅读系统统一发现和读取，用户委派使用指定书籍；探索欲按主题选材，无匹配时不能擅自读取最近一本。
- 阅读有进展但没完成目标，不等于欲望失败。活动结果由各消费者分别更新欲望、精力和记忆。
- 自由探索按联网配置执行搜索、抓正文和消化，排除自身程序提示词与创作文件；无可读来源时不生成知识。网页委派与书籍读取共用资料沉淀能力。
- 网页问卷由浏览器后台任务处理，结果在活动页展示；聊天中的受理回执不代表任务已完成。
- 桌面观察与采样是现有能力，通用电脑输入控制闭环尚未实现。

## 源码入口

- `nyx/activity/facade.py`、`starter.py`、`lifecycle.py`：准入、执行、打断与恢复。
- `nyx/activity/scheduler.py`、`store.py`：排期与持久化。
- `nyx/activity/exploration.py`、`creation.py`、`browser_survey.py`、`observe.py`：具体活动。
- `nyx/runtime.py`、`nyx/reading/facade.py`：触发与统一书库读取。
