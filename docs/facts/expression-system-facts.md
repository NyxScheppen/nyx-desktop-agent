# 表达系统基本事实

> 记录职责与关键边界；回复图节点、预算、协议、字段和状态机查源码。

## 职责与行为

- 处理普通回复、讨论、工具规划执行、主动搭话、碎碎念及等待用户回答。
- 回复使用角色卡身份、当前状态、历史和时间资料；快慢通道都可使用用户事实与对话段，慢通道再做分析、工具或更完整上下文组装。
- 讨论模式可显式启用、禁用或自动判断；专门的知识与资料工具保持来源归因。
- 回复期间，同角色兼容的补充输入可在安全边界并入当前回合；独立提问、讨论或批注等边界会隔开回合。
- 明确撤回会取消尚未执行的旧动作；已发生的动作及回执必须保留。副作用结果未知时不能当作普通失败自动重放。
- 最终正文、等待关系与输入覆盖一并提交；重放复用终局并补归档，不重新生成或重复执行已确认工具。
- 前端提交请求的锁与等待回复分开。等待或软超时期间仍可补充输入，迟到终局只结束其实际覆盖的等待。
- 主动搭话消费互动欲并等待回答；碎碎念更轻，不消费互动欲，也不建立同样的等待关系。
- 读书提问复用统一等待机制；回答时补入原段落及该书相关资料。
- 解析失败进入重试或降级，不把空文本或坏 JSON 伪装成成功回答；用户未回答的超时不写成记忆事实。
- 最终回复应以本轮真实工具结果和执行证据为依据，不把模型设想写成已经执行。

## 源码入口

- `nyx/expression/facade.py`、`store.py`：表达门面、历史与等待。
- `nyx/expression/pipeline.py`、`tool_pipeline.py`：回复与工具执行图。
- `nyx/expression/prompt.py`、`classifier.py`、`mutter.py`：上下文、分类与轻量表达。
- `nyx/reading/companions.py`、`nyx/runtime.py`：读书互动与实际触发。
