# 基础设施基本事实

> 记录基础能力的职责和边界；接口、配置字段、存储结构和参数查源码。

## 配置与存储

- `config.yaml` 提供公开运行配置，`nyx/config.py` 负责加载；环境变量承载密钥和部署覆盖项，不把凭证写入前端构建变量。
- `NYX_DATABASE_URL` 为空时使用 SQLite，非空时使用 PostgreSQL；宿主与角色数据隔离，checkpoint 使用对应后端的 saver。
- 数据库迁移与事务集中在 `nyx/db.py`。角色卡和工作区文件与数据库一起构成恢复所需数据，迁移和备份不能只考虑数据库。

## 模型、工具与评估

- `nyx/llm/client.py` 统一模型调用、结构化输出、工具、重试和用量；视觉入口在 `nyx/llm/vision.py`。embedding 使用本地模型。
- `nyx/tools/registry.py` 注册和执行工具。现有能力包括本地搜索、工作区文件、联网搜索、网页抓取、知识检索、研究与活动任务；业务通过装配提供具体能力。
- 工具观测与可靠执行回执不同：前者用于诊断，后者用于避免副作用重放。结果未知不能等同于安全失败。
- `nyx/eval/` 记录模型产出、角色一致性及 token；不直接重写回复。角色偏离可经回调沉淀失败经验，但这不等于自动在线修正输出。

## 装配与传输

- `nyx/harness.py` 是 Nyx 内部的进程内插件装配核心，提供能力上下文、依赖排序、构建与启动检查。
- Nyx 的领域插件、回调、工具与路由在 `nyx/plugins.py`；装配与运行底座只供 Nyx 使用，保留在主项目内。
- 浏览器和桌面通过 REST/SSE 接入；`nyx/transports/onebot.py` 通过 OneBot v11 正向 WebSocket 连接 NapCat/LLOneBot。
- OneBot 仅接指定账号私聊，向配置的本人 QQ 发送角色 THINK/SPEAK/ASK；THINK 带“💭 内心话”前缀。出向队列持久保存并在重连后续发。
- OneBot 出向是至少一次，极端崩溃窗口可能重复一次；它与浏览器 SSE 使用不同的投递路径。
- OneBot 对进入事务前的锁等待超时按阶段退避重试；发送成功后只重试确认，连接重建保留待确认状态。退出清理有界，未释放队列由租约恢复；SQL 执行和提交失败仍按真实故障上报。共享锁记录慢等待、慢持锁及任务来源。
- 根凭证、设备配对及 HTTPS 入口由现有宿主/API/前端配合；操作见 [本地操作](../operations.md)、[线上操作](../deployment.md)。
