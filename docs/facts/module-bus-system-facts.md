# 模块与事件总线基本事实

> 记录职责与关键边界；投递协议、事务实现、字段和重试参数查源码。

## 职责与行为

- 事件总线负责持久受理、消费者投递、重试、通知与 SSE 广播；事件标识和因果链用于追踪来源。
- 事件已保存、某消费者已完成、前端已展示是三个不同事实。SSE 不能证明业务副作用已经完成。
- 持久投递按至少一次处理，消费者需要幂等；失败可重试，耗尽后留下可观察的死信。
- 本地业务状态、派生事件与消费标记可以原子提交；跨模块依靠各自投递推进，不存在覆盖模型、文件和网络的全局回滚。
- 模型和外部 I/O 在短事务外准备；提交后唤醒或广播失败不反向改写已经提交的业务结果。
- 模块之间既有事件通信，也有直接查询与编排调用；不能假设 Facade 完全禁止互调。
- 运行时管理周期触发、后台任务、监督与恢复。关闭时先停止新准入，再排空任务，最后关库；超时不能提前释放仍被使用的资源。
- 宿主按角色隔离总线和执行状态，共享观察再分别投递；角色切换不会把旧请求转交给新角色。
- SSE 支持角色范围内的游标续传；重连时前端也会重拉所需快照，广播通道不是业务存储。
- 对话续接有独立的输入顺序与原子终局边界，归档完成和终局已交付仍须分别判断。

## 源码入口

- `nyx/events/bus.py`、`routing.py`、`event.py`：事件、投递与路由。
- `nyx/subscriptions.py`、`nyx/runtime.py`：订阅和调度监督。
- `nyx/app_context.py`、`nyx/plugins.py`、`nyx/main.py`：宿主、装配与启动。
- `nyx/db.py`：事务与迁移；`nyx/harness.py`：插件装配核心。
