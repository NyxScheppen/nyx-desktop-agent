# 阅读系统基本事实

> 记录职责与关键边界；解析算法、格式坐标、字段、阈值和状态转换查源码。

## 职责与行为

- 以角色为单位管理 EPUB、段落、用户与 Nyx 的进度、笔记、划线、书签及阅读互动。
- EPUB 导入解析正文和有限格式信息，不直接保存、执行原始 HTML；重复正文不会生成第二本书。
- 用户与 Nyx 的位置分开保存。共读时 Nyx 逐段追赶用户，用户回翻不重复触发已经处理的前进内容。
- 后台活动读取与用户共读使用同一书库和 Nyx 阅读进度；活动通过阅读门面发现和读取书籍。
- 段落特征先决定是否触发碎碎念、提问或联想；只有需要生成内容时才调用模型，提问共享频率控制。
- 阅读触发依据段落特征、精力和欲望压力；不计算角色审美敏感度或人格分数，实际表达读取当前内在文档。
- 读书提问与统一表达等待关系一起提交；回答时提供原段落、书籍概况和该书相关知识。
- 原文按来源沉淀为证据与知识，进度保存可用于恢复；书中人物或第一人称不能被当成用户事实。
- Nyx 的即时阅读反应先进入缓冲，在章节或整本边界整合；原文沉淀与反应整合是不同路径。
- 用户笔记、纯划线和书签属于用户内容；给 Nyx 看的批注是显式操作，不自动把所有笔记写进记忆。
- 进度更新和前端异步响应受书籍、角色与版本约束，旧回包不能覆盖新书或当前进度。

## 源码入口

- `nyx/reading/facade.py`、`store.py`：书库、进度、笔记与后台准入。
- `nyx/reading/epub.py`、`segmenter.py`：正文解析；`impulse.py`、`companions.py`：互动。
- `nyx/reading/integration.py`：资料沉淀与阅读反应整合。
- `frontend/src/stores/readerStore.ts`、`frontend/src/components/reading/`：阅读器状态与界面。
