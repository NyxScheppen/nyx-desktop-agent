# 探索系统重设计 · 逐层地牢（文字 Roguelike）

> 状态：设计稿（brainstorming 产物，待转实现计划）
> 日期：2026-08-27
> 涉及：探索（activity/exploration）、遭遇（encounter）、记忆/欲望老系统接缝、道具（hook）、NPC（hook）
> 关联 spec：`14-activity`（探索归属）、`19-encounter`（遭遇归属）、`09-memory-facade` / `11-desire`（接缝）

## 1. 问题与目标

**现状痛点**（用户原话「探索的东西很奇怪」「遭遇太奇怪」「看不到她探索了什么」）：

- 探索是「无根 LLM 话题 + 本地全盘 grep」的固定 8 步链（`web_enabled=false` 默认走本地检索），产出落一个覆盖式 `exploration_note.md`，没有结构、看不到每一步干了什么。
- 遭遇是块边界随机事件（`_BLOCK_PROBABILITY=0.3`，模板选项 + 固定后果），与探索完全脱节。
- 搜索/发现没有牵动精力或欲望，探索是孤立的一次性动作。

**目标**：把探索重设计成「在真实世界里下副本」的文字 Roguelike——真实网站/书籍/文件即地牢节点，精力=燃料、欲望=目标，逐层深入、有根遭遇、可托管、发现与遭遇全部落进记忆/欲望老系统。

## 2. 核心概念（一句话定位）

> **真实世界即地牢**：地牢的节点不是虚构房间，而是真实的搜索/下载/本地文件/资料库条目。逐层向下，越深越接近某个真相。

四个已锁定的设计决策：

1. **逐层地牢（深度优先）**：一场 run 从「种子欲望」出发，逐层向下，越下越深、越接近真相。
2. **精力=燃料，欲望=目标**：进节点/下楼耗精力，耗尽半路结束；挖到核心发现 = 满足种子欲望 = 赢。
3. **节点真实**：真实网站 / 真实书籍 / 本地文件 / 资料库，绝不编造；搜不到就填「死路」。
4. **有根遭遇**：遭遇从当前节点的真实内容长出来（内容、选项、后果三者都长在真实节点上）。

## 3. Run 生命周期

### 3.1 起点

- **主路径**：探索欲（`DesireType.EXPLORATION`）达峰 → 生成短期欲望 → 它成为 run 的「种子」（含「探索什么」方向，`seed.desire_id` + `seed.topic`）。
- **手动**：用户手动「去探索」也能开；无种子时**优先从最近记忆/她的欲望里取方向**，不凭空 LLM 编话题（堵住「探索得奇怪」的源头之一）。

### 3.2 楼层（骨架可控）

- 每层 **3 个节点槽**（数字先做常量，MVP 定 3，不做配置项）。
- 槽位由「本层主题」的真实搜索 / 本地检索 / 资料库填充：搜到几个真实结果就填几个，**不足 3 个用「死路」槽补**。
- 每层另有 1 个固定**安全房**槽（第 4 槽），不占节点槽。

### 3.3 每层一轮（turn）

1. 你（或托管时尼克斯）选一个节点走进去。
2. 耗精力（进节点 -X）→ 拿真实内容（`web_fetch` 网页 / 读文件 / 摘录）。
3. 产出一个「发现」：笔记 / 知识 / 遭遇钩子 / 道具钩子。
4. 决定「下楼」「继续本层另一个节点」或「进安全房」。

### 3.4 下楼（追真实线索）

- 从本层真实发现里挑一条线索 → 沿它搜更深/更具体 → 生成下一层主题与槽位。
- 越深越贵：下楼精力消耗递增，但发现更深。

### 3.5 安全房（休息点）

每层一个固定安全房槽，走进去三合一：

1. **回燃料**：恢复精力（+X，复用现有 `rest` 的 +30 语义）。
2. **整理沉淀**：把本层发现整理成记忆（触发记忆写入/反思）。
3. **安全撤退窗口**：在此撤退 = 正常结算、收获不打折。

> 资源环：**下注**（耗燃料进节点）→ **收获**（发现）或 **碰壁**（死路白耗）→ **安全房**（回燃料 + 沉淀 + 可撤退）→ 再下注 or 收手。

### 3.6 终点（赢/输）

- **赢**：挖到「核心发现」→ `satisfy(seed.desire_id, goal_met=True)` → 结算落袋。
- **输/撤退**：精力耗尽 → 半路结束，已写记忆保留、道具钩子打折。
- **主动停**：你或她说「够了」→ 正常结算。

**节点词汇（四种）**：真实节点 / 死路 / 遭遇（深险节点）/ 安全房。

## 4. 结果形状与老系统接缝

### 4.1 run 结果形状（`ACTIVITY_END` 的 `result`，type=`free_exploration`）

```jsonc
{
  "type": "free_exploration",
  "seed": { "desire_id": "…", "topic": "…" },
  "outcome": "won | retreated | exhausted",
  "floors_cleared": 3,
  "summary": "…",                                   // 兼容现有 summary 键
  "core_discovery": "…",                            // 赢时才有
  "knowledge": [ { "topic": "…", "content": "…" } ],
  "new_topics": [ "…" ],
  "encounters": [ { "memory": {…}, "desire": {…} } ],
  "loot": [ { "name": "…", "desc": "…", "source": "exploration" } ],   // 道具 hook
  "npcs": [ { "name": "…", "description": "…" } ]                       // NPC hook
}
```

### 4.2 记忆写入 —— 复用三条**已有**缝

| 记什么 | 走哪个方法 | 类型/tag |
|---|---|---|
| 这场 run 本身（summary + core_discovery + 值得一提发现） | `remember_activity`（改 `_activity_memory_fields` 里 free_exploration 映射：`notes/findings` → `summary/core_discovery`） | SHORT_TERM / `free_exploration` |
| 提取的知识点 | `remember_knowledge`（原来只有读书用，现在探索也产） | LONG_TERM / `knowledge` |
| 遭遇后果 | `remember_encounter`（已有，读 `consequences.memory`） | SHORT_TERM / `encounter` |

一场 run 落 **1 条 run 记忆 + N 条知识记忆 + M 条遭遇记忆**，全部走 `_persist_memory` 统一入库尾段（去重→embed→建边→矛盾检测→淘汰），**不新建记忆抽象**。

### 4.3 欲望写入 —— 复用两条**已有**缝

| 什么 | 走哪个方法 |
|---|---|
| 核心发现 = 满足探索欲 | `satisfy(seed.desire_id, goal_met=True)`（已由 `ACTIVITY_END → satisfy_from_activity_end` 驱动，result 带上 `seed.desire_id` + outcome） |
| 新话题 = 新欲望种子 | 强烈新兴趣 → `add_long_term`；一般好奇 → 只留在 run 记忆（不新增欲望，防膨胀） |

### 4.4 道具 / NPC hook（本次只留缝）

- `result.loot` / `result.npcs` 字段，未来各自独立 spec 读 `ACTIVITY_END` 的 result 即可接上。
- **不建道具表、不建 NPC 实体、不造 `ITEM_DROP` 事件**（反冗余）。

## 5. 遭遇（有根）

### 5.1 生成

- **触发**：进入「险」节点——深楼层节点，或内容被 LLM 判定为「有争议/需抉择」。普通节点只给**小事件卡**（标题 + snippet + 「继续吗」）。
- **生成（轻）**：一次 LLM 调用，输入 `(该节点真实内容 snippet, 本层主题, 尼克斯当前欲望/精力/情绪)`，输出一个有根遭遇：
  - **情境**：长在真实内容上（搜到有争议话题 → 「要不要深入这个有争议的观点」）。
  - **选项 = 真实动作**：「打开这条链接深挖 / 换话题 / 记下来 / 放弃这条线」。
  - **后果真实**：`{ energy_delta, desire_delta, emotion, memory:{content,summary} }`，与现有 `choose` 后果形状兼容。
- **结构稳定、内容现长**：遭遇结构（情境+选项+后果）是稳定契约（可 mock、可测），内容每次从真实节点长出来。

### 5.2 去留

- **删**块边界随机遭遇（`try_block_boundary` / `_BLOCK_PROBABILITY` 等）——正是「遭遇太奇怪」的元凶。
- 遭遇统一两个来源：**探索中有根生成**（5.1，新）+ **成长时刻**（读完书，`on_activity_end` 保留）。

## 6. 托管模式

- **决策点**：每层「选哪个节点」、每层「下楼/继续/进安全房」、遭遇「选哪个选项」。
- **手动（默认）**：每个决策点暂停，等用户选。
- **托管**：一键切「托管」，之后每个决策点由尼克斯自己选。决策依据 = 种子欲望方向 + 剩余精力 + 情绪 + 人设，**轻 LLM 决策**（可 mock）。
- **随时接管**：托管中用户点任意选项 = 立即接管；整场 run 一个开关，不做逐节点托管开关（反冗余）。

## 7. 前端呈现

- **调性**：Darkest Dungeon 暗黑地牢风（近黑暖棕底、暗金描边、火把橙黄渐变、serif 哥特字体、暗红警示），少 emoji。
- **HUD 顶栏**：火把·精力血条（燃料）、欲望（目标）、深度（第 N 层 ↓）、托管开关。
- **本层 4 槽**：真实节点 / 死路 / 安全房，每个节点标类型 + 精力消耗 + 是否可能触发遭遇。
- **下楼条**：追真实线索往下。
- **展开地图**：显示已走过的楼层（来过 ◆ / 当前 ◆ / 未到），列每层进过哪些节点。
- **道具栏**：底部 6 格占位（道具系统后续接入）。
- **内心独白**：尼克斯权衡要不要再下一层（呼应「重叙事」）。

## 10. 范围 / 反冗余 / 未决项

**本次做**：探索逐层地牢 + 有根遭遇 + 托管 + 记忆/欲望接缝 + 前端暗黑地牢 UI + 道具/NPC 留 hook。

**本次不做（hook 预留）**：道具系统、NPC 系统——各自独立 spec。

**反冗余自查**：

- 记忆/欲望写入全部复用现有 facade 方法，不新建记忆/欲望抽象。
- 楼层槽位数、精力消耗、安全房回复量先用**常量**（同现有 `_MAX_STEPS`），不新增配置项，除非实现时确实需要调。
- 托管整场一个开关，不做逐节点开关。
- 道具/NPC 只留 `result` 字段，不建表/实体/事件。
- 删块边界随机遭遇，避免「有根 + 随机」双轨并存。

**未决项（转实现计划时定）**：

1. 探索链是继续用 LangGraph（带 interrupt 的 StateGraph）还是改成 facade 内的异步可恢复状态机——倾向后者（决策暂停等输入更自然），实现计划时定。
2. `new_topics` 判定「强烈新兴趣 vs 一般好奇」的阈值（一次 LLM 判断还是规则）。
3. 核心发现「挖到」的判据：达到目标深度？还是 LLM 判定「这条线到头了、真相已明」？倾向后者 + 深度上限兜底。
